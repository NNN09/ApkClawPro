# 合规与账号安全设计落地说明（ROADMAP §6 C1–C6）

> 对应 `docs/ROADMAP.md` 第 6 节。本文档说明各项措施的**落地位置、默认值、调优方式**，
> 并对各消息渠道/第三方 App 的自动化风险做事实性告知。原则不变：
> **不做对抗平台检测的功能**——官方 API 优先、系统能力优先、执行节奏受频控约束、不可逆操作人工确认。

## 措施对照

| # | 措施 | 落地状态 | 说明 |
|---|---|---|---|
| C1 | 官方 API 优先 | 已达成（渠道层，保持） | 钉钉 Stream / 飞书 OAPI / QQ Bot / Discord Gateway / Telegram Bot API / 微信官方 Bot；设备侧优先 F9 系统 Intent 工具 |
| C2 | 操作场景分级 | F9 已落地 | 一级场景（系统 App/设置）：Intent/系统 API；二级场景（第三方 App UI 自动化）：受 C5/C6 约束 |
| C3 | 频控与人速 | **本批落地** | 见下方「C3 设置」；实现：`compliance/AdmissionControl.kt` + 配置页「合规」卡片 |
| C4 | 不可逆操作人工确认 | F2 已落地 | `DangerousOpDetector` + `UserDecisionGate`；C6 策略不弱化它（AUTO 仍确认危险操作） |
| C5 | 用户知情与授权 | **本批落地** | 配置页风险告知 + 第三方自动化总开关；见「C5 设置」 |
| C6 | 按 App 自动化策略 | **本批落地** | 每 App 三态策略；见「C6 设置」 |

C3/C5/C6 代码在 `com.apk.claw.android.compliance` 包（纯 JVM 逻辑，可单测），
接入点：`ChannelSetup`（任务准入）、`TaskOrchestrator`（启动登记/熔断计数）、
`DefaultAgentService`（每次工具调用的策略门）。全部**活读**：配置页改动即时生效，无需重启或重连。

## C3 设置（频控与人速）

> 目的：避免高频/深夜/反复失败的自动化触发平台风控，同时保护设备与电量。
> 设计取舍：**静默时段、冷却、熔断只作用于自动任务**（当前为 F7 定时任务；
> 将来 F8 事件驱动同样标注 automated）。真人通过渠道发来的消息永远放行——真人节奏本身就是"人速"。

| 设置 | 默认值 | 语义 |
|---|---|---|
| 夜间静默 | 关 | 静默时段（默认 22:00–07:00，可改，支持跨零点；起止相同=全天）内到达的自动任务被**跳过**，并回渠道一条说明；不重新排队。手动消息不受影响 |
| 自动任务最小间隔 | 5 秒 | 距上次任务启动不足该间隔的自动任务被跳过（0=关） |
| 全局频率上限 | 10 次/分钟 | 滑动窗口 60s 内全局任务启动数超限 → 新到达消息（含手动）被拒并回渠道说明（0=关） |
| 单渠道频率上限 | 5 次/分钟 | 同上，按 Channel 分别计数（0=关） |
| 熔断阈值 | 5 次 | 连续失败（F3 任务状态 FAILED 计数；等待超时/取消不计）达到阈值后：自动任务暂停（回渠道说明）；手动任务放行但附熔断提示；任一任务成功即自动清零。可在配置页手动"复位熔断"（0=关） |

实现要点：熔断计数与 F3 历史同点落账（`TaskOrchestrator.recordHistory`），
频率窗口/冷却为进程内状态（重启清零——异常风暴通常在单次运行期内，跨重启不残留）。

## C5 设置（知情与授权）

- 配置页「合规」卡片顶部为常驻**风险告知**：第三方 App 自动化可能触发其反自动化风控（账号受限/封禁）。
- 「第三方 App 自动化总开关」默认**开启**（保持产品"遥控手机"的核心能力）；关闭后：
  - 对第三方 App 的改动类 UI 操作（open_app 进入、tap/long_press/swipe/input_text/scroll_to_find/repeat_actions）被拒并回渠道说明；
  - 系统 App、观察类工具（读界面/截图）、system_key 导航、F9 系统级 Intent 工具不受影响；
  - 系统判定：包管理器 `FLAG_SYSTEM`；查询失败按第三方保守处理（宁多拦不误放）。
- 未知包名时总开关语义按"第三方"处理。

## C6 设置（按 App 自动化策略）

未配置策略的 App（含全部系统 App）：维持 F2 行为——仅危险操作（发送/支付/删除等关键词）需确认。
用户可为单个包名配置三态策略（配置页添加/删除，整体替换保存，上限 50 条）：

| 模式 | 语义 |
|---|---|
| AUTO 全自动 | 与未配置一致；**危险操作仍受 F2 全局确认**（硬底线，策略永不强于安全底线） |
| CONFIRM 全部确认 | 该 App 内每次改动类操作都经渠道人工确认（2 分钟超时视为取消）；比 F2 更严，命中后不再重复 F2 弹窗 |
| BLOCK 禁止 | 该 App 内改动类操作直接拒绝并回渠道说明；观察/导航离开/系统工具仍可用（Agent 需能看清界面后退出） |

建议给**支付/银行/社交类** App 配置 `CONFIRM` 或 `BLOCK`（如
`com.eg.android.AlipayGphone`、`com.unionpay`、`com.tencent.mm` 等）。
项目不内置任何名单：名单无法完备、且"默认行为不突变"更可预期；
列表为空时产品行为与历史版本完全一致。

## 平台条款风险告知（事实性）

自动化他人平台/第三方 App 均存在条款与风控风险，本产品只是工具，使用者自负其责：

- **消息渠道**：各平台开放平台 API 均有频率/内容/行为限制，超限调用可能被限流或封禁。
  本产品只连官方 Bot API 且不伪装人类；渠道侧风险由平台规则决定。
- **第三方 App UI 自动化**：多数 App 的服务条款禁止非人工操作；平台风控可能检测
  （点击节奏、无障碍使用特征、行为时段等）并限制/封禁账号。本产品**不做任何对抗检测的功能**，
  只通过频控/静默/熔断约束节奏、通过 C6 让高风险 App 显式确认或禁用，从源头降低误伤与激怒风控的概率。
- **设备系统能力**：F9 系统工具（闹钟/媒体/勿扰等）属本机系统 API，无平台条款问题，
  但仍受 C3 频控约束以保护设备与电量。
